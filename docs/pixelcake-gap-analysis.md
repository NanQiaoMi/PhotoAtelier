## 0. 一页结论

**结论：两个产品不在同一层。** 光屿是「本地、隐私优先、色彩可解释的批量调色/局部处理引擎」；像素蛋糕是「商业摄影 AI 精修 + 选片交付 + 多端云协作平台」。真正要补的不是「某个滑杆」，而是三层能力：**人像精修深度、工作流闭环、分发与性能地基**。

| 判断 | 内容 |
|---|---|
| 差距最大的三块 | ① 人像精修（祛瑕疵/磨皮/美型/五官/妆容/证件照）② 选片—交付工作流（评级筛选/AI 挑图/客户交付/联机）③ 平台、性能与分发（原生 ARM、多端、撤销等基础体验） |
| 光屿已领先/可守 | 色彩管理与 LUT 合同、逐图自适应 LUT、可测量的局部建议、批量安全与逐张报告、离线隐私、246 项自动化测试与保守安全约束 |
| 补齐原则 | **补「人像精修核心 + 本地选片 + AI 追色 + 分发地基」，不追「云生态 + 生成式全家桶 + 排版/视频」**——后者与本地单机定位冲突且成本远超单人可维护范围 |
| 如果 90 天只做三件事 | ① **人像 v1**（人脸解析 + 祛瑕疵 + 高低频磨皮 + 牙齿/眼白 + 肤色统一）② **工作流地基**（HEIC/拖放/撤销/评级筛选/导出增强）③ **AI 追色 + 调色工具扩展**（HSL/曲线/颜色分级） |
| 如果只做一件 | **人像 v1**。它决定用户是否还愿意把本应用称作「修图软件」；色彩与批量是光屿的存量优势，人像是增量入口。 |
| 不建议追 | 云空间/ERP/账号计费体系、像素苏打排版、像素吐司视频、全量生成式 AI 工具箱、六端同步。把它们留给商业平台；光屿用「离线 + 买断/自托管 + 可审计」差异化。 |

## 1. 产品定位与商业模式差异

| 维度 | 像素蛋糕 v10（官方文档口径） | 光屿 Photo Atelier | 差距性质 |
|---|---|---|---|
| 定位 | 「专业 高效 亿级像素品质，商业级 AI 图像创作软件」，面向商业摄影机构/影楼/工作室（B2B） | 本地照片分析 + 批量调色 + 局部/人像细节的 macOS 桌面工具 | 定位差异，不是单纯功能差 |
| 用户与场景 | 婚纱/儿童/写真/证件照/全家福等批量出片；强调「即拍、即修、即排、即选、即交付」 | 单机摄影师/爱好者；文件夹级配方、逐张自动方案、导出报告 | 光屿缺交付链路 |
| 计费 | 年套餐按**导出张数**计费（¥299/800 张 ≈0.37 元/张 → ¥18,800/90,000 张 ≈0.21 元/张），另有创意点数、云存储、会员等级；不退款、不结转 | 无账号、无联网、无计费；本地处理 | 商业模式不同 |
| 平台 | Windows x64、macOS（Intel/Apple Silicon 安装包）、鸿蒙 PC、iPad、iPhone、Android 六端；云空间跨设备 | macOS 13+；**仅 Intel x86_64 实机验证**，Apple Silicon 未验收；未公证 | 分发差距（P0） |
| 云端与协作 | 云空间（个人/团队/企业）、NAS 公共盘、联机拍摄（6 品牌）、ERP 对接、芝士/苏打/吐司/曲奇生态 | 全程本地，零网络代码（反向 grep 证实无 `URLSession` 等） | 战略分叉：不建议正面追 |
| 隐私 | 半云端：细节分割在线、处理在端；需登录与云空间 | 分析/处理/导出均离线；默认剥离位置与相机隐私元数据 | **光屿优势** |
| 开放性与可验证性 | 闭源；能力以官方文档为准，效果无法独立复核 | MIT；246 项测试、自检 harness、逐张批处理 JSON 报告、证据文档 | **光屿优势** |

**定位结论**：不要在「六端 + 云 + ERP + 按张计费」的战场正面竞争；把光屿做成「**离线也能完成 80% 常用商业精修的本地工作站**」，用隐私、可解释、买断/自托管和色彩精度换市场。

## 3. 逐域差距明细

### 3.1 导入与图库

| 项 | 像素蛋糕 | 光屿 | 影响 |
|---|---|---|---|
| 输入格式 | JPG/PNG/TIFF/RAW（机型适配清单未公开） | `jpg/jpeg/jpe/png/tif/tiff` + 39 种 RAW 扩展名候选（系统解码器实际支持为准） | HEIC 缺失直接影响 iPhone 素材；AVIF/WebP 影响网络素材 |
| 导入方式 | 文件夹/图片拖入、拖到 App 图标建项目、联机实时导入、二次导入追加 | 仅 `NSOpenPanel` 选文件夹（`AppModel.swift:230-237`），无 drag&drop、无单文件、无二次导入 | 日常用第一道摩擦 |
| 图库模型 | 项目制、云项目/NAS、缩略图状态、回收站 30 天 | 扁平文件列表（`ContentView.swift:148`），无项目/回收站/排序筛选 | 工作流从「批量交付」退化为「一次导出」 |
| 浏览与对比 | 网格/单图/对比/参考视图（钉住参考）、全效果模式 | 单图 + 前后拖动对比 + 「原尺寸检查」512/768/1024 区域对比 | 光屿的像素级检查更强；缺多图对比/参考图 |

### 3.4 调色、RAW、AI 色彩

| 项 | 像素蛋糕 | 光屿 | 判断 |
|---|---|---|---|
| 基础影调 | 曝光/对比/饱和/白平衡/曲线/HSL/色彩编辑器/颜色分级/细节/颗粒/镜头/校准 | 曝光/WB/对比/饱和/高光/阴影/五区 EV/旋转/透视/自动水平/Lensfun 畸变 | 光屿在**色彩合同与安全检查**上更严谨，工具数量明显少 |
| 曲线 | 总曲线/参数曲线/RGB/亮度/单通道/曲线吸管 | 仅五区 EV 单调曲线（`TonalCurve.swift`） | 缺 RGB 曲线 |
| HSL/分级 | 8 色相 HSL + 色轮色彩编辑器 + 高光/阴影/中间调三色轮 | 无 | 缺 |
| 颗粒/光晕/暗角 | 颗粒分区域、镜头暗角 | 辉光/暗角/颗粒（`CreativeEffects.swift`） | 部分具备；镜头暗角/CA 未启用 |
| LUT/预设 | 70+ 滤镜、预设分类/导入导出/XMP/Cube、组合预设、预设叠加 | 18 个 LUT +「原色」、`.cube` 严格校验、5 输入空间、逐图 9 组适配、LUT 诊断、域外保护 | **光屿质量体系更强，数量与场景化不足** |

| AI 色彩风格 | 15 种动态生成参数（先分析光影再生成数值） | 18 个静态 LUT +「原色」+ 逐图适配 | 光屿的逐图适配思路已接近「动态」，但缺参考图追色 |

| 输出色彩 | sRGB；ProPhoto（引擎侧宣称） | sRGB/Display P3，16-bit PNG/TIFF，OKLab 色域映射 | 光屿输出链路更可核验；缺 AdobeRGB/ProPhoto/CMYK |

### 3.8 光屿的优势（要主动产品化，而不是只做追赶）

1. **色彩可解释**：LUT 输入/输出空间合同、域外平滑降权、肤色/中性保护、色域映射、表格诊断（`LUTCompatibility.swift`、`OutputGamut.swift`）；像素蛋糕无法独立复核其色彩处理。
2. **测量驱动的局部建议**：九宫格建议不自动改图、覆盖率/亮度依据可查看、原尺寸复测（`RegionalAdjustmentSuggestions.swift`、`LocalLightGuidance.swift`、`NativeInspection.swift`）。
3. **批量安全**：原子写入、不覆盖、坏图隔离、逐张 JSON 报告、原图哈希不变（`BatchProcessor.swift`、`app-smoke.json` 断言）。
4. **隐私**：无网络代码、默认剥离位置/相机元数据；对不愿上传客片的摄影师是硬需求。
5. **可验证性**：246 项测试 + 自检 harness + 证据分级文档；可作为「可信修图」的差异点。

## 4. 补齐路线（按价值 × 可行性 × 差异化排序）

评分：**价值**（对目标用户）、**可行性**（单机/本地/无生成模型前提下）、**差异化**（是否能形成光屿的独特卖点），各 1–5 分；总分决定 P 级。

#### P0-2 人像 v1（4–8 周，最高价值）

| 项 | 内容 |
|---|---|
| 目标 | 覆盖商业修图最高频链路：**祛斑祛痘 → 中性灰/高低频磨皮 → 牙齿美白 → 眼白提亮 → 面部肤色统一**，全部本地、可关闭、可调强度、有「保留特征」开关 |
| 技术路线（不依赖第三方模型） | ① **人脸解析 lite**：用 `VNDetectFaceLandmarksRequest`（76 点）+ 颜色分类 + 边缘引导滤波，产出软蒙版：皮肤/眉毛/眼（虹膜/眼白）/唇/牙齿/发际线；新增 `FaceSemanticMask` 模型 + 缓存（按图/按脸）。② **祛瑕疵**：在皮肤蒙版内做 band-pass（DoG）残差，局部鲁棒阈值（median + k·MAD）检出斑点/痘，按面积/对比度过滤；用**高低频分离修复**（替换高频缺陷为邻域高频中值，保低频光影），强度/保留模式（祛痘留斑/保留痣）可调；单次修复限幅，避免蜡像感。③ **中性灰/高低频**：低频=引导模糊后的光影层，高频=原图−低频；提供「平整、立体（提亮/压暗）、高频增强、低频平整、纹理、光泽、清晰」滑杆；沿用现有 ±0.12 EV 单次限幅与 alpha 加权。④ **牙齿美白**：牙齿蒙版内降低 b\*（黄）并提升 L，高斯羽化保护牙龈/唇缘，限制 ΔE。⑤ **眼白提亮**：眼白蒙版内降红通道偏差 + 提亮，保护虹膜与眼神光。⑥ **面部肤色统一**：多人脸各自皮肤 Lab 统计，以中位/最亮肤色为参考做局部 tone 曲线，保留纹理与妆面 |
| 涉及文件 | `FaceRegionAnalysis.swift` 扩展、`ContentSelection.swift`、`LocalDetailProcessing.swift`、`PhotoEngine.swift`、`Models.swift`（新设置 + 配方版本 10）、新增 `BlemishRemoval.swift`/`FaceSemanticMask.swift`、`Tests/PhotoCoreTests/` 新测试文件 |
| 风险 | 检测/蒙版误伤（眼眉嘴、发丝、胡须、妆面）；痘痣与皮肤纹理混淆；不同肤色/光位表现差异大。必须提供蒙版预览 + 手动涂抹擦回（可复用现有画笔蒙版组件） |
| 验收 | 合成斑点/渐变肤色夹具：检出率与误检率有阈值；修复后眼眉嘴/痣样本不变（像素差 < ε）；真实人像子集做前后对比评审（记录为人工评价，不冒充自动验收）；配方 v1–v10 兼容；`make check` 全绿 |

## 6. 不建议追的差距（明确边界）

| 不追项 | 理由 | 替代策略 |
|---|---|---|
| 云空间/团队账号/ERP/按张计费 | 与本地隐私定位冲突；需后端、合规、计费、客服体系，非单人可维护 | 离线 + 买断/自托管；配方 JSON 可版本管理；未来可选「用户自备 WebDAV/iCloud」同步 |
| 六端同步（iPad/iPhone/Android/鸿蒙） | 每端都是独立产品与验收面 | 先做好 macOS 原生；移动端可做「只读选片/交付」轻应用（P2 再议） |
| 生成式 AI 全家桶（40 项工具、方糖大模型） | 算力/许可/合规成本高；与离线冲突；效果无法本地保证 | 不自研；若用户有云服务，做显式可选的外部工具接口（标注数据出境） |
| 像素苏打排版 / 像素吐司视频 / 像素曲奇选版 | 独立产品线，不属于修图引擎职责 | 导出通用格式（JPG/TIFF/PSD 后续）交给专业排版/视频工具 |
| 自研 16bit RAW 引擎 | 需机型标定、去马赛克、降噪长期投入；系统解码已可覆盖多数 | 继续用 `CIRAWFilter` + 明确机型边界；评估 LibRaw 作为可选后端 |
| 「效果等同像素蛋糕」的宣称 | 现有文档已诚实声明差距；夸大无法验证 | 用「可验证的本地能力」表述，给出测试与评审证据 |

## 7. 风险与开放问题

### 7.1 风险

1. **算法质量风险**：经典 CV + Vision 的祛瑕疵/磨皮效果可能达不到商业 AI 的稳定性，尤其深肤色、强妆面、发丝、遮挡；必须提供强度限制、可关闭、手动擦回与人工评审，不做「自动完美」承诺。
2. **模型许可风险**：若后续引入第三方人脸解析/分割模型，需逐项核对训练数据与权重许可（商用/再分发）；建议优先用系统 Vision + 自研经典算法，模型方案单独立项做合规评估。
3. **ARM 构建风险**：Lensfun/GLib 交叉编译可能反复；备选方案是 Apple Silicon CI 构建或基于 Rosetta 的过渡说明。
4. **配方兼容风险**：人像/追色新增字段必须走版本门禁（当前 v9），旧配方保持像素兼容；撤销栈不能破坏现有自动方案「差值只叠加一次」语义。
5. **性能/内存风险**：人像多蒙版 + 全分辨率细节 + 批量会推高 RSS（历史峰值已约 0.9–1.2 GB）；P0-6 基准必须先于大规模功能扩展。
6. **范围蔓延风险**：人像 v1 必须锁定五项能力，美型/妆容/证件照按 P1 排期，否则 90 天目标无法收敛。

### 7.2 开放问题（需要用户决策）

1. **产品目标**：这是个人/开源自用工具，还是要发展成可售卖产品？决定是否投入公证、ARM、客服、教程。
2. **优先赛道**：人像精修 / 选片交付 / 调色与 AI 追色 / 分发基建，先做哪条？
3. **外部模型与云服务**：是否允许引入第三方 Core ML 模型或可选云 API？涉及许可与隐私取舍。
4. **真实照片评审集**：能否提供 20–30 张可用的授权人像/场景照片？这决定「效果验收」能否落地。
5. **Apple Silicon 硬件/CI**：是否有 M 系列机器或可用 CI 用于原生构建与运行验证？
